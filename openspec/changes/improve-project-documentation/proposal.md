## Why

MenuKita's README contains accurate implementation notes but reads primarily as an internal engineering log, making the project difficult for judges, collaborators, and new contributors to understand quickly. The repository also lacks an explicit license despite being public and intended for collaboration.

## What Changes

- Reorganize the README using the presentation-ready information hierarchy demonstrated by the `stellar-garden` reference while rewriting every section for MenuKita's AI food-compatibility context.
- Add concise project evidence, product flow, architecture, tech stack, feature, setup, environment, test, deployment, troubleshooting, safety, and collaboration sections.
- Preserve MenuKita's evidence and safety boundaries without importing blockchain-specific claims or terminology.
- Add an MIT `LICENSE` file and declare MIT metadata in `package.json`.
- Keep links, commands, test counts, routes, dependencies, and deployment guidance grounded in the current repository.

## Capabilities

### New Capabilities
- `project-documentation`: Defines the repository's public-facing documentation, setup guidance, technical overview, safety boundaries, and license declaration.

### Modified Capabilities

None.

## Impact

This change affects `README.md`, `LICENSE`, `package.json`, and the governing OpenSpec artifacts only. It does not change runtime behavior, API contracts, dependencies, credentials, or deployment state.
